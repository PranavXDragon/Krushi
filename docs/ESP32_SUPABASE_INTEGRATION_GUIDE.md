## 1. System Pipeline Overview

```
+-----------------------------------------------------------------------------------------+
|                                    DATA FLOW PIPELINE                                   |
+-----------------------------------------------------------------------------------------+

  [1. Physical ESP32 Node]
          |
          | (1) Reads sensors (Temp, Hum, Ethylene, GPS, Battery)
          | (2) Formats JSON payload with monotonic sequence
          | (3) HTTPS POST to Supabase REST endpoint
          v
  [2. Supabase Cloud Database]
          |
          | Stores raw record in `esp32_telemetry` table
          | Flags record with `synced_to_local = false`
          v
          +-----------------------+-----------------------+
          | (Option A: Webhook)   | (Option B: Polling)   |
          | Supabase Webhook      | Local backend polls   |
          | POSTs new row to API  | unsynced rows via SDK |
          +-----------------------+-----------------------+
          v
  [3. AgriTrace FastAPI Backend & Local DB (`agritrace.db`)]
          |
          |-- Receives raw ESP32 record
          |-- Resolves active shipment and thresholds
          |-- Validates monotonic sequence order ($Seq_i = Seq_{i-1} + 1$)
          |-- Computes recursive SHA-256 hash chaining ($H_i = \text{SHA256}(\dots, H_{i-1})$)
          |-- Evaluates excursions (High Temp / Ethylene Spike) -> logs Alerts
          |-- Saves into local SQLite/Postgres database
          |-- Batches records for Merkle Tree Ledger Anchoring
          |-- Broadcasts real-time JSON via WebSocket (`/ws/telemetry`)
          v
  [4. AgriTrace Operations Dashboard (React + Vite)]
          |
          |-- Receives WebSocket push update ($< 200\text{ms}$)
          |-- Updates Truck-Centric Compartment Overlay (green/red)
          |-- Updates real-time telemetry Recharts graph
          |-- Updates open alerts badge and count
          |-- Updates cryptographic block chain explorer
```

## 2. Supabase Setup (SQL Schema)

In your [Supabase Project Dashboard](https://supabase.com/dashboard) $\to$ **SQL Editor**, execute the following SQL script to create the incoming telemetry table:

```sql
-- 1. Create table for incoming ESP32 sensor telemetry
CREATE TABLE IF NOT EXISTS public.esp32_telemetry (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    device_id TEXT NOT NULL DEFAULT 'AGRITRACE-001',
    shipment_id TEXT,
    sequence BIGINT NOT NULL,
    temperature NUMERIC(5, 2) NOT NULL,
    humidity NUMERIC(5, 2) NOT NULL,
    gas_ethylene NUMERIC(6, 2) NOT NULL,
    latitude NUMERIC(9, 6) DEFAULT 19.0760,
    longitude NUMERIC(9, 6) DEFAULT 72.9982,
    battery NUMERIC(4, 1) DEFAULT 94.5,
    solar_power_mw NUMERIC(6, 1) DEFAULT 320.0,
    network_state TEXT DEFAULT 'online',
    synced_to_local BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 2. Index for high-performance querying by device and sync state
CREATE INDEX IF NOT EXISTS idx_esp32_telem_synced ON public.esp32_telemetry(synced_to_local, created_at);
CREATE INDEX IF NOT EXISTS idx_esp32_telem_device ON public.esp32_telemetry(device_id, sequence);

-- 3. Enable Row Level Security (RLS) or allow anon insert for IoT nodes
ALTER TABLE public.esp32_telemetry ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow anon insert from ESP32" 
ON public.esp32_telemetry 
FOR INSERT 
TO anon 
WITH CHECK (true);

CREATE POLICY "Allow anon select and update for backend sync" 
ON public.esp32_telemetry 
FOR ALL 
TO anon 
USING (true);
```

## 3. Connecting Supabase to the Local Backend

You can connect Supabase to your local backend using **either** of these two methods:

### Method A: Supabase Database Webhook (Instant Push - Recommended)
1. In your Supabase Dashboard, go to **Database** $\to$ **Webhooks**.
2. Click **Create a new Webhook**:
   - **Name**: `agritrace_telemetry_webhook`
   - **Table**: `esp32_telemetry`
   - **Events**: Check `INSERT`
   - **Type**: HTTP Request
   - **HTTP Method**: `POST`
   - **URL**: `http://your-server-address:8000/api/v1/telemetry/supabase-webhook`  
     *(If running locally during development, use an ngrok or localtunnel URL e.g. `https://xxxx.ngrok-free.app/api/v1/telemetry/supabase-webhook`)*
3. When ESP32 inserts a row, Supabase immediately calls the endpoint.
4. The local backend computes the hash chain, commits it to `agritrace.db`, and broadcasts it live to the React dashboard!

### Method B: Background Poller / Sync Endpoint
1. Add your Supabase credentials to `backend/.env`:
   ```bash
   SUPABASE_URL=https://your-project.supabase.co
   SUPABASE_KEY=your-anon-or-service-role-key
   ```
2. Trigger the sync via REST:
   ```bash
   POST http://localhost:8000/api/v1/telemetry/supabase-sync
   ```
   Or call `sync_from_supabase_table()` on a periodic schedule (e.g. every 10 seconds).

HTTPClient http;
http.begin("https://<project-ref>.supabase.co/rest/v1/esp32_telemetry");

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/v1/telemetry/supabase-webhook" `

  -Headers @{ "Content-Type" = "application/json" } `
  -Body (@{

    gas_ethylene = 13.9
    battery = 94.2
    latitude = 19.0760

    network_state = "online"
  } | ConvertTo-Json)
```

**Result**:
- Record is saved to local `agritrace.db`.
- SHA-256 hash is chained to Sequence #54.
- Live WebSocket broadcasts the reading.
- The React dashboard at `http://localhost:5173/` updates immediately!
